# Tableau Connector Setup Guide

---

## Requirements

- **Tableau Cloud** or **Tableau Server** with REST API access
- A user account with **Site Administrator Explorer** or **Site Administrator Creator** role
- A **Personal Access Token (PAT)** generated by the administrator account
- PAT authentication must be enabled on the site (enabled by default on Tableau Cloud)

---

## Connector capabilities

1. **What resources does the connector sync?**  
   This connector syncs:  
   — Sites (the Tableau site the connector is authenticated against)  
   — Users (all users on the site with email, full name, site role, auth setting, and last login)  
   — Groups (Tableau groups with membership information)  
   — Licenses (license tiers: Creator, Explorer, Viewer, Unlicensed — users are assigned based on their site role)  
   — Projects (Tableau projects with Read/Write permission assignments for users and groups)  
   — Workbooks (Tableau workbooks with granular permission assignments: Read, Write, Filter, ViewComments, AddComment, ExportImage, ExportData, ShareView, ViewUnderlyingData, WebAuthoring)  
   — Views (individual dashboards/views within workbooks, with the same granular permissions as workbooks minus Write)

   > **Note**: If a workbook has `showTabs=true`, view-level permissions are inherited from the workbook and not synced independently.

2. **Can the connector provision any resources? If so, which ones?**  
   The connector can provision:  
   — User accounts (create new users on the site with email, site role, and IDP/MFA authentication)  
   — User deletion (remove users from the site)  
   — Site role assignments (grant/revoke site-wide roles like SiteAdministratorCreator, Creator, Explorer, Viewer, etc.)  
   — License assignments (grant/revoke license tiers — Creator, Explorer, Viewer — by updating the user's site role)  
   — Group memberships (add/remove users from groups)  
   — Project permission assignments (grant/revoke Read, Write permissions for users and groups)  
   — Workbook permission assignments (grant/revoke all 10 workbook permissions for users and groups)  
   — View permission assignments (grant/revoke view permissions for users and groups, only when parent workbook has `showTabs=false`)

   > **Note**: Group-based permission assignments on projects, workbooks, and views are supported. Grant expansion propagates permissions through group memberships.

## Connector credentials

1. **What credentials or information are needed to set up the connector?**  
   This connector requires:  
   — Tableau Cloud or Tableau Server instance  
   — Personal Access Token Name  
   — Personal Access Token Secret  
   — Server Path (base URL of the Tableau instance)  
   — Site ID / Content URL (optional for Tableau Server default site)

   **Args**:  
   `--access-token-name` - The name of the Personal Access Token used to authenticate ($BATON_ACCESS_TOKEN_NAME)  
   `--access-token-secret` - The secret value of the Personal Access Token ($BATON_ACCESS_TOKEN_SECRET)  
   `--server-path` - Base URL of your Tableau instance, without the `/api/<version>` suffix (e.g., `https://us-east-1.online.tableau.com`)  
   `--site-id` - The content URL / site ID (e.g., `mycompany`)  
   `--api-version` - Optional API version override, defaults to `3.27` ($BATON_API_VERSION)

2. **For each item in the list above:**

   - **How does a user create or look up that credential or info?**

     **Personal Access Token (PAT):**

     1. Sign in to your Tableau Cloud or Tableau Server instance.
     2. Click on your profile icon in the top-right corner and select **"My Account Settings"**.
     3. Scroll down to the **"Personal Access Tokens"** section.
     4. Enter a **Token Name** (this will be your `--access-token-name` value).
     5. Click **"Create new token"**.
     6. Copy the **Token Secret** immediately — it is displayed only once. This is your `--access-token-secret` value.

     > **Important**: The user account used to create the PAT must have **Site Administrator Explorer** or **Site Administrator Creator** role.

     **Documentation:**
     - Tableau Cloud: https://help.tableau.com/current/online/en-us/security_personal_access_tokens.htm
     - Tableau Server: https://help.tableau.com/current/server/en-us/security_personal_access_tokens.htm

     **Server Path:**

     1. This is the base URL of your Tableau instance **without** the `/api/<version>` suffix. The connector appends `/api/<version>` automatically using the `--api-version` flag (defaults to `3.27`).
     2. For **Tableau Cloud**: `https://<pod>.online.tableau.com` where `<pod>` is your region (e.g., `us-east-1`, `eu-west-1a`, `ap-southeast-2`). You can find the pod in your browser URL bar when signed in.
     3. For **Tableau Server**: `https://<your-server-hostname>`.
     4. The API version can be overridden with `--api-version`. See the [REST API version reference](https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_concepts_versions.htm) for valid versions.

     **Site ID (Content URL):**

     1. For **Tableau Cloud**: When signed in, look at the URL in your browser. The site ID appears after `/site/` in the URL: `https://us-east-1.online.tableau.com/#/site/<site-id>/home`.
     2. For **Tableau Server**: Navigate to the site settings or check the URL. For the default site, the site ID can be left empty.
     3. Documentation: https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_concepts_auth.htm#the-site-attribute

   - **Does the credential need any specific scopes or permissions?**  
     Yes. Personal Access Tokens in Tableau inherit the full permissions of the user who created them. There are no separate OAuth scopes. The PAT must be created by a user with:

     - **Site Administrator Explorer** role (minimum for full read access)
     - **Site Administrator Creator** role (recommended for full read + write access)

   - **Is the list of scopes or permissions different to sync (read) versus provision (read-write)?**  
     The same PAT is used for both operations, but the minimum required role differs:

     - **Syncing (read-only)**: **Site Administrator Explorer** — can list all users, groups, projects, workbooks, views, and their permissions.
     - **Provisioning (read-write)**: **Site Administrator Creator** or **Site Administrator Explorer** — needed to create/delete users, update site roles, manage group memberships, and add/remove permissions on projects, workbooks, and views.

     > **Note**: A user with Viewer or Explorer role will NOT have sufficient access. The API returns only resources visible to the authenticated user.

   - **What level of access or permissions does the user need in order to create the credentials?**  
     - The user must have **Site Administrator Explorer** or **Site Administrator Creator** site role.
     - On Tableau Server, a **Server Administrator** can also create PATs.
     - PAT creation must be enabled on the site. On Tableau Cloud it is enabled by default. On Tableau Server, the server administrator must enable it in server settings.

## Resource Details

### Sites

- **Description**: The Tableau site the connector is authenticated against. Acts as the top-level resource in the hierarchy.
- **Children**: Users, Groups, Projects
- **Entitlements**: Site roles (SiteAdministrator, SiteAdministratorCreator, SiteAdministratorExplorer, ServerAdministrator, Creator, Explorer, ExplorerCanPublish, Viewer, ReadOnly, Unlicensed)
- **Provisioning**:
  - Grant: Update a user's site role
  - Revoke: Set a user's site role to Unlicensed

### Users

- **Description**: All users on the Tableau site
- **Traits**: User trait with email, status, and last login
- **Provisioning**:
  - Create new users with email, site role, and authentication method (SAML IDP or TableauIDWithMFA)
  - Delete users (remove from site)
- **Profile attributes**:
  - `first_name`: First name (parsed from full name)
  - `last_name`: Last name (parsed from full name)
  - `login`: Email address
  - `user_id`: Tableau user ID
  - `auth_setting`: Authentication setting

### Groups

- **Description**: Tableau groups for organizing users
- **Traits**: Group trait
- **Entitlements**:
  - `member` — Membership in the group
- **Provisioning**:
  - Grant: Add users to groups
  - Revoke: Remove users from groups
- **Profile attributes**:
  - `group_id`: Tableau group ID
  - `group_name`: Group name

> **Note**: Server Administrators (`ServerAdministrator` site role) are skipped during group membership sync because they are server-level admins, not site-scoped users.

> **Important — "All Users" Group**: Tableau automatically adds every user to the built-in "All Users" group. This group **cannot be modified via the API** — attempting to add or remove users will result in a `400 Bad Request` error from Tableau. The connector still syncs "All Users" membership grants because it is useful to see the base role each user holds at the site level. However, Grant and Revoke operations on this group are not supported by Tableau.

> **Important — Minimum Site Role**: Some groups may be configured with a "Grant role on sign in" minimum site role. If a user belongs to such a group, Tableau will reject any attempt to lower the user's site role below that minimum (e.g., revoking a license to set them to "Unlicensed"). To resolve this, the user must first be removed from the group with the minimum site role constraint before their license can be downgraded.

### Licenses

- **Description**: Tableau license tiers that determine feature access
- **Traits**: Role trait
- **Static Resources** (4 license types):
  - `Creator` — Full authoring, data prep, and publishing capabilities
  - `Explorer` — Browse, interact, and publish with existing data sources
  - `Viewer` — View and interact with published dashboards
  - `Unlicensed` — No access to Tableau site features
- **Entitlements**:
  - `member` — License is assigned to user (static entitlement)
- **Provisioning**:
  - Grant: Assign a license to a user by updating their site role
  - Revoke: Remove a license by setting the user's site role to Unlicensed

> **Note**: License assignment is based on site role mapping. For example, the Creator license includes users with the `Creator` and `SiteAdministratorCreator` site roles.

> **Important — License Revoke Constraints**: Revoking a license (setting a user to "Unlicensed") will fail if the user belongs to a group with "Grant role on sign in" configured. Tableau enforces that a user's site role cannot be lower than the minimum site role required by any group they belong to. The error message from Tableau will be: *"Site role of link user that belongs to license upon login cannot be lower than minimum site role of group"*. To resolve this, remove the user from the constraining group first, then revoke the license.

### Projects

- **Description**: Tableau projects that organize workbooks into logical folders
- **Children**: Workbooks
- **Entitlements** (2 permissions):
  - `Read` — View the project and its contents
  - `Write` — Modify the project and its contents
- **Provisioning** (users and groups):
  - Grant: Assign Read or Write permission on a project
  - Revoke: Remove a permission from a project

### Workbooks

- **Description**: Tableau workbooks that contain views/dashboards
- **Children**: Views
- **Entitlements** (10 permissions):
  - `Read` — View the workbook
  - `Write` — Modify the workbook
  - `Filter` — Apply filters to views in the workbook
  - `ViewComments` — View comments on views
  - `AddComment` — Add comments to views
  - `ExportImage` — Export views as images
  - `ExportData` — Export underlying data
  - `ShareView` — Share views with other users
  - `ViewUnderlyingData` — View the underlying data of views
  - `WebAuthoring` — Edit views in the browser
- **Provisioning** (users and groups):
  - Grant: Assign any of the 10 permissions on a workbook
  - Revoke: Remove a permission from a workbook
- **Grant expansion**: When a group has a workbook permission, all group members inherit that permission.

### Views

- **Description**: Individual dashboards/views within workbooks
- **Entitlements** (9 permissions — same as workbook minus Write):
  - `Read`, `Filter`, `ViewComments`, `AddComment`, `ExportImage`, `ExportData`, `ShareView`, `ViewUnderlyingData`, `WebAuthoring`
- **Provisioning** (users and groups):
  - Grant: Assign permissions on a view (only when parent workbook has `showTabs=false`)
  - Revoke: Remove permissions from a view (only when parent workbook has `showTabs=false`)

> **Important — showTabs and View Permissions**:
> - When a workbook has `showTabs=true`, all views in the workbook **inherit** the workbook's permissions.
> - In this case, view-level permissions cannot be set, granted, or revoked independently.
> - The connector automatically detects this and skips view entitlements/grants for workbooks with `showTabs=true`.

## Tableau REST API

This connector uses the Tableau REST API for all operations.

**Documentation:**
- REST API Reference: https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api.htm
- Authentication: https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_concepts_auth.htm
- Permissions: https://help.tableau.com/current/api/rest_api/en-us/REST/rest_api_concepts_permissions.htm

**Pagination:**
- Uses `pageSize` and `pageNumber` query parameters (1-based page numbering, default page size: 100)
- Responses include a `pagination` object with `pageNumber`, `pageSize`, and `totalAvailable`
